# Контекст для Claude Code (читай це першим)

Якщо ти Claude Code, щойно запущений у цьому репозиторії (`C:\python\worker` на цій
машині) — це нотатка від Claude з іншої сесії (на іншому ПК), яка вела цей проєкт
і зараз допомагає власнику віддалено, лише через скріни консолі/браузера, без
прямого доступу до цієї машини. Тут усе, що треба знати, щоб продовжити без
перепитувань.

## Що це за проєкт

Бот для гри Perfect World 1.3.6 (клієнт `ElementClient.exe`, вікно `ComebackPW`),
що керує персонажем **у фоні** — через `PostMessage`/`BitBlt`, без активації вікна,
миша й клавіатура лишаються вільними. Архітектура: кадр вікна за тік → пул
пайплайнів (`app/pipelines/*.py`, кожен — одна дія: атака, лут, повернення на
місце, лікування пета...) → список дій → виконавець шле їх у вікно гри.

Один процес (`main.py`) тримає веб-інтерфейс на `http://127.0.0.1:8765` — там
конструктор пайплайнів, керування кожним персонажем окремо, живе прев'ю екрана,
калібрування кліком. **Єдина точка входу:** `.venv\Scripts\python main.py`
(без аргументів = сторінка; `main.py run` = без сторінки, CLI). Сам себе
перезапускає, якщо впав (процес-батько + дитина `--serve`).

## Персонажі й профілі

`config/windows.json`: `profiles` — пул налаштувань пайплайнів («як грати»),
`characters` — нік персонажа (прочитаний OCR з екрана, табличка над портретом)
→ який профіль і чи ввімкнено. Нік **закріплюється** за вікном після першого
підтвердження — у картці персонажа є кнопка «закріпити» для ручного виправлення,
якщо OCR схибив.

Зараз у конфізі:
- **CEKXU** → `Дру на волках 22-25 (1280x720)` — друїд, фармить вовків.
- **BroWorker** → `Анігілятор мобів поряд 0+ (1280x720)` — б'є все поряд.
- `Дру на волках 22-25` (без суфікса) — оригінал під 1440x1080, лишається для
  персонажів, які й досі в цій роздільності (Elinalise, cookie).

### Чому два варіанти кожного профілю (1440x1080 і 1280x720)

Інтерфейс PW136 **не масштабується** під розмір вікна гри — кожен елемент
прибитий пікселями до свого кута/краю екрана незалежно від роздільності
(перевірено живцем: портрет персонажа на (100,28) однаково і на 1440×1080, і
на 1280×720). Тому координати всіх зон розпізнавання (де шукати текст, іконки,
кнопки) прив'язані до конкретного розміру вікна. Профіль `(1280x720)` — це той
самий профіль, але кожна зона зсунута відповідно до того, який край (лівий/
правий/верх/низ/центр) вона тримає. Методика: якщо в 1440×1080-зони однакові
відступи зліва й справа — вона центр-прив'язана; якщо впирається в правий
край (right == 1440) — право-прив'язана (новий x = 1280 − старий_відступ_справа);
і так само по вертикалі. Відносні офсети (клік відносно вже знайденого шаблона —
рюкзак, лавка, список) не чіпаються: вони однакові на будь-якій роздільності.

## Діагностичні скрипти (лежать поруч із `main.py`)

Усі самодостатні, не потребують запущеного бота, самі шукають вікно гри
(`find_windows`) якщо hwnd не вказано. Запуск: `.venv\Scripts\python diag_*.py`.

- **`diag_capture.py`** — чи взагалі вдається зняти кадр вікна (DWM-композиція,
  сесія процесу гри vs бота, IsIconic/ClientRect). Перше, що запускати, якщо
  прев'ю в браузері каже «вікно гри недоступне» чи щось схоже.
- **`diag_nick.py`** — чому нік не читається: 5 кроків (tesseract встановлено? іконка
  над портретом знайдена? маска ніка не порожня? сирий OCR? підсумок).
- **`diag_position.py`** — один кадр: читання координат/висоти в налаштованій
  зоні + сканування сусідньої смуги на випадок, що зона зсунута не туди.
- **`diag_position_watch.py`** — те саме, але **з РЕАЛЬНИМ конфігом профілю**
  (не з дефолтів!) і кілька тіків поспіль — показує внутрішній стан
  `PositionPipeline` (candidate/jump/misses), бо саме читання раз на кадр не
  показує, чому `pos.known` не стає `True`. Нік можна не вказувати — прочитає
  сам. `python diag_position_watch.py [нік] [секунд] [hwnd]`.
- **`diag_list.py`** — повторює `return_home._find_point()`: заголовок «Список» →
  права колонка → OCR рядок за рядком → відсоток збігу з назвою точки. Для
  «нема точки «фарм»», коли вона видима в грі.

## Що вже полагоджено в цій сесії (хронологія)

1. Конструктор у веб-інтерфейсі: кнопка «створити профіль» була заблокована
   без вибраного персонажа — тепер ніколи не блокується; додано «видалити».
2. Порядок пайплайнів: `combat_ready` — бойовий шлюз на спільній дошці,
   `return_home`/`death_return` закривають його, поки координати не
   підтверджені; `target_search`/`attack` чекають. `run_order` розставляє
   пошук/лут/атаку в кінець такту незалежно від порядку в конфізі.
3. На другій машині (ВМ) OCR ніка не працював — виявилось, **Tesseract-OCR
   не встановлений** (`C:\Program Files\Tesseract-OCR\tesseract.exe` не існує;
   це системний інсталятор, не з pip/git). Треба ставити окремо на кожній машині:
   https://github.com/UB-Mannheim/tesseract/wiki
4. Прев'ю в браузері падало з «вікно гри недоступне» для щойно знайденого,
   ще не закріпленого вікна — через те, що оверлей «квадрат лута» (увімкнений
   за замовчуванням) намагався взяти конфіг персонажа, якого ще нема в
   конфізі, і валив увесь запит кадру. Полагоджено (`_loot_config` повертає
   `None` замість падіння).
5. `return_home` не знаходив точку «фарм» у «Списку», хоча вона там видима —
   OCR на одній машині стабільно читав «фарм» як «форм» (одна літера а↔о,
   інше згладжування шрифту), збіг 0.75 був на межі порога 0.6. Поріг
   знижено до 0.5 (сусідні назви зон зовсім інші, не плутає).
6. Додано періодичний рядок стану в консоль (`AppSettings.status_log_every`,
   за замовчуванням 20с) — той самий текст, що на картці вікна в браузері,
   щоб бачити прогрес без скріна сторінки.

7. Автооновлення: `python main.py` на старті робить `git pull --ff-only` (лише якщо нема
   незакомічених змін; не блокує старт, якщо git/мережі нема; `--no-update` вимикає).
8. **Лаги, коли запущено кілька ботів.** Виміряно на 12-ядерній машині: чиста логіка
   пайплайнів дешева (~4 мс/тік, 1 вікно ≈ 150 тіків/с, 4 вікна ≈ по 50), OpenCV-потоки й
   tesseract паралелляться нормально — тобто на сильному ПК лагу не відтворити. На слабкій
   ВМ (мало ядер) навантаження росте лінійно з числом вікон і впирається в CPU. Зроблено:
   - кеш читання координат/висоти (`app/vision/digits.py`): персонаж стоїть — маска цифр
     та сама — `tesseract.exe` не запускається взагалі (раніше 2 запуски/с на вікно);
   - у рядку стану в консолі й на картці вікна тепер видно розбивку часу тіка:
     `⏱ 16.2 к/с · кадр 14 / логіка 5 / дії 3 мс · важчі: return_home 31 мс`.
     **Якщо знову лагає — спершу глянь цей рядок**: великий «кадр» = знімок вікна (BitBlt/
     PrintWindow) важкий, «логіка» = розпізнавання, «дії» = паузи між кліками. Якщо сума
     тіка наближається до 60 мс (за замовчуванням `poll_interval` 0.06) — збільш «Кадр, с»
     у картці персонажа до 0.12–0.2: боту не потрібні 16 к/с.

## На чому зараз зупинились (АКТИВНА ПРОБЛЕМА)

На ВМ персонаж **BroWorker** стабільно (хвилинами, не зрідка) показує
«координат нема» в статусі — `position`-пайплайн не може прочитати координати
з панелі вгорі праворуч, хоча:
- профіль правильний (`Анігілятор мобів поряд 0+ (1280x720)`, client_size
  збігається з реальним вікном 1280×720);
- зона цифр у профілі `(1068, 22, 78, 14)` виміряна й підтверджена живцем на
  ІНШОМУ персонажі (CEKXU, та сама роздільність) — там читається чисто;
- форма персонажа, HP, «Список», рюкзак/лавка — усе інше працює нормально
  (підтверджено живими логами: `sell` відпрацьовує повні цикли, `form_keep`
  бачить іконку форми).

Останній крок — попросив прогнати `diag_position_watch.py` (без аргументів,
сам читає нік і бере реальний профіль) просто зараз, поки бот у цьому стані,
і заразом подивитись очима в самій грі, чи на місці панель з координатами
(може бути перекрита чатом/вікном, або персонаж десь, де цього шматка
інтерфейса просто нема). **Відповіді ще не отримано** — це наступний крок.

Якщо побачиш результат `diag_position_watch.py` із порожніми читаннями —
дивись на збережений `diag_pos_full.png`/аналогічний кадр з `diag_position.py`
перед тим, як щось міняти в коді: можливо, причина не в калібруванні, а в тому,
що персонаж не в грі (екран логіна, діалог, завантаження) — так уже було на
іншій машині в цій самій сесії.

## Корисні команди

```powershell
cd C:\python\worker
git pull                                  # підтягнути код/конфіг з іншої машини
.venv\Scripts\python main.py              # єдина точка входу, сторінка на :8765
.venv\Scripts\python -m pytest -q         # 360 тестів, мають проходити всі
.venv\Scripts\python diag_position_watch.py   # діагностика поточної проблеми
```

Після правок коду сервер треба перезапустити (Ctrl+C і наново, або просто
вбити процес `--serve` — батьківський процес підніме свіжий сам). Конфіг
(`config/windows.json`) краще міняти через `PUT /api/config`, а не редагуванням
файлу напряму, якщо сервер уже запущений — інакше його пам'ять розійдеться
з диском і наступне збереження з інтерфейсу перезатре правки.

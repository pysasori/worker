# PW136AutoBot

Бот для Perfect World 1.3.6, який працює з вікном гри **у фоні**: гру можна перекрити
іншими вікнами, миша й клавіатура лишаються вільними. Під капотом — віконні повідомлення
(`PostMessage`) і копія поверхні вікна з композитора Windows (`BitBlt`), тобто те саме,
що робить UOPilot, але на Python.

## Запуск

Одна команда:

```bash
.venv\Scripts\python main.py
```

Відкриється сторінка http://127.0.0.1:8765. Більше нічого запускати не треба: сторінка сама знаходить вікна
гри (раз на 5 с), читає нік кожного персонажа з екрана, і **всі налаштування — там**: профілі
(пул, копії, перейменування), який профіль у якого персонажа, «запускати», автостарт, наглядач, порт.

Процес `main.py` ще й стежить за сервером: якщо той упав, піднімає знову. Усередині наглядач
перезапускає сесію вікна, чиї кадри перестали рухатись.

Параметри потрібні рідко: `--port`, `--host`, `--config`, `--log-level DEBUG`, `--no-browser`,
`--no-supervise` (без батьківського процесу — для налагодження).

Нік читається з екрана й **закріплюється за вікном**. Якщо OCR схибив — у картці вікна можна вказати
нік вручну; хибне читання запам'ятається як псевдонім персонажа.

Вимоги до клієнта: віконний режим (не fullscreen exclusive), не згорнутий,
розмір під профіль (зараз 1440x1080).

## Ідея

```
    вікно "main"                                    вікно "alt"
        │                                               │
   [ один кадр за тік ]                          [ один кадр за тік ]
        │                                               │
   ┌────┴────────┬──────────────┬───────────┐           …
   │             │              │           │
pet_heal   target_search    attack        loot    periodic_keys
   │             │              │           │           │
   └─────────────┴──────┬───────┴───────────┘───────────┘
                        │
              [ виконавець дій ] → PostMessage у це вікно
```

Кадр знімається **один раз** і роздається всім пайплайнам. Кожен сам вирізає з нього
свою зону, тому всі бачать один момент часу, а гра не смикається від зайвих запитів.

## Конструктор

Пайплайни не викликають один одного. Замість цього кожен оголошує, що він **віддає**
на спільну дошку і що йому **потрібно** звідти:

```
target_search  →  target  →  attack   (б'є, поки ціль жива)
                          →  loot     (тисне F2 на кадрі смерті)
pet_heal       →  pet
periodic_keys     нічого не потребує
```

Рантайм із цього сам вибудовує порядок: постачальник завжди раніше за споживача,
тому лут бачить смерть цілі тим самим кадром. Якщо ввімкнути атаку без пошуку цілі,
бот скаже про це на старті, а не працюватиме мовчки й марно.

Складати можна як завгодно: лишити тільки `target_search` з `"target_key": null` —
буде чистий монітор цілі без дій; вимкнути `loot` — бій без збору; додати `attack`
з іншою клавішею на друге вікно через `overrides`.

## Шари

| Шар | Тека | Відповідальність |
|---|---|---|
| Захоплення | `app/capture/` | знайти вікно, зняти кадр. Не знає про гру |
| Ввід | `app/input/` | послати клавішу/клік у вікно. Не знає про гру |
| Зір | `app/vision/` | чисті функції над картинкою: прочитати смужку HP |
| Пайплайни | `app/pipelines/` | рішення: що робити, побачивши такий кадр |
| Рантайм | `app/runtime/` | цикл вікна, виконання дій, кілька вікон паралельно |
| Конфіг | `app/config/`, `config/windows.json` | профілі інтерфейсу і список вікон |

Правила, які тримають це чистим:

- пайплайн **не** робить скрін і **не** тисне клавіші — він повертає список дій;
- `vision` не знає про пайплайни, `capture`/`input` не знають про гру;
- уся калібровка — у конфізі, у коді немає магічних координат;
- кожне вікно має свій екземпляр пайплайнів і свій стан.

Завдяки цьому пайплайн тестується на збереженому скріні без гри (`tests/`), а веб-інтерфейс
пізніше просто читатиме `Orchestrator.statuses()` і писатиме `config/windows.json`.

## Що де налаштовується

| Де | Що |
|---|---|
| `config/windows.json` і конструктор | клавіші, інтервали, пороги HP, списки мобів, розмір квадрата лута |
| код (`app/vision`, `app/pipelines`) | координати зон, кольори, пороги розпізнавання |

Технічні поля не зникли: у шапці є перемикач «технічні», під ним видно зони, кольори
й пороги. У звичайній роботі вони не потрібні, бо все, що може з'їхати, шукається за виглядом:

| Що | За якою ознакою знаходиться |
|---|---|
| смужка HP цілі | найдовший червоний відрізок у смузі рядків угорі |
| рамка пета | червона смужка + фіолетова під нею; синя мана відрізняє рамку персонажа |
| іконка «Лавка» | золоті монети в бірюзовому кільці |
| знос спорядження | жовта або червона іконка зброї справа вгорі |

Тому рамку пета можна пересунути мишею куди завгодно — бот знайде її сам.

## Конфіг

`config/windows.json` має дві частини:

- **profiles** — вигляд інтерфейсу клієнта: координати смужок, клавіші, інтервали.
  Один профіль на всі вікна з однаковим UI.
- **windows** — конкретні клієнти: ім'я, як знайти вікно, який профіль, точкові `overrides`.

Другий клієнт додається так:

```json
{ "name": "alt", "profile": "pw136_1440x1080", "match": { "index": 1 },
  "overrides": { "combat": { "attack_key": "f4" } } }
```

## Веб-інтерфейс

- **Конструктор** — блоки пайплайнів з усіма налаштуваннями. Форми будуються зі схем,
  тому новий пайплайн з'являється в інтерфейсі сам. Прапорець «своє для цього вікна»
  переносить налаштування блока в `overrides` конкретного вікна.
- **Вікна** — список клієнтів, увімкнення, номер клієнта, живий стан кожного пайплайна.
- **Ручні кнопки** — атака, лут, вибір цілі, лік піта і довільна клавіша з кількістю
  натискань та інтервалом. Працюють і коли бот зупинений.
- **Екран вікна** — кадр гри з намальованим квадратом пошуку лута і знайденими підписами.
  Це і є калібрування: постав персонажа біля дропу і підбери пороги, поки квадрат не
  почне бачити саме те, що треба.

## Новий пайплайн

1. Файл у `app/pipelines/`, клас з `type_name`, `config_model` і методом `process(ctx)`.
2. Якщо він щось віддає або споживає — `provides` / `requires`.
3. Декоратор `@register` над класом.
4. Імпорт у `app/pipelines/__init__.py`.
5. Блок у профілі конфіга.

Рантайм, CLI і майбутній веб підхоплять його самі — правити їх не треба.

## Вибір мобів за назвою

У блоці «Пошук цілі» є список «Бити тільки цих» і «Не чіпати цих». Назва читається
з рамки цілі один раз на ціль, тому це дешево. Порівняння **нечітке**: OCR плутає
окремі літери й підставляє латинські двійники, тому «Гopный вapвao» все одно
збігається з «Горный варвар». Поріг схожості налаштовується.

Двигун читання перемикається в тому ж блоці:

| Двигун | Швидкість | Кирилиця |
|---|---|---|
| `tesseract` | ~140 мс | точно, потрібен tesseract у системі + `models/tessdata/rus.traineddata` |
| `rapidocr` | ~40 мс | стандартна модель читає кирилицю латиницею, придатна для цифр і латиниці |

Якщо прочитати не вдалось, бот б'є як раніше: краще зайвий моб, ніж простій.

## Тести

```bash
.venv\Scripts\python -m pytest tests -q
```

Ганяються на справжньому кадрі гри (`tests/fixtures/`), гра для них не потрібна.

## Що вже вміє

| Пайплайн | Що робить | Зв'язки |
|---|---|---|
| `target_search` | читає смужку HP цілі, віддає її стан, бере нову ціль; уміє вибирати мобів за назвою | віддає `target` |
| `attack` | б'є, поки ціль жива; нова ціль — удар одразу | потребує `target` |
| `loot` | після смерті тисне підбір до N разів, перевіряючи землю між натисканнями | потребує `target` |
| `pet_heal` | HP піта нижче порогу — тисне клавішу лікування | віддає `pet` |
| `repair` | поза боєм раз на годину: рюкзак → Лавка → «Починить все» → «Да» | самостійний |
| `dialog_guard` | закриває зависле модальне вікно гри клавішею Esc | самостійний |
| `periodic_keys` | тисне задані клавіші по таймеру | самостійний |

Блоки згруповані за категоріями (`pet`, `combat`, `loot`, `service`) — так вони й показані
в конструкторі. Нова категорія додається одним полем `category` у класі пайплайна.

## Довга робота

```bash
.venv\Scripts\python main.py web              # веб-сервіс (він же тримає бота)
.venv\Scripts\python tools\watchdog.py       # наглядач: перевірка щохвилини
```

Наглядач пише `logs/watchdog.log`, помічає завислі кадри і піднімає бота, якщо той упав.
Події самого бота — у `logs/web.log`.

Стара односкриптова версія лишилась у `legacy/`.
